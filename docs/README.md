# Project Documentation

`docs/` contains accepted, long-lived knowledge about ClinkZ.

Content enters this directory only after it has been reviewed and accepted through a workspace or another explicit project process.

## Sections

- `requirements/` — accepted product and system requirements.
- `architecture/` — current architecture descriptions and system boundaries.
- `adr/` — architecture decision records explaining important choices.
- `contracts/` — durable cross-component semantic and interface contracts.

Active investigation, unfinished proposals, raw inputs, and unresolved questions belong in `workspace/`, not here.
